# 08 产品形态：Harness本地工作台

版本UI-PF-1，2026-11-07。状态：产品方向已确认，功能未实现；独立评审状态见根[评审报告](../../docs/design-review-surfaces.md)。

| ID | 最终目标与首版范围 | 状态/来源 |
|---|---|---|
| UI-PF-01 | Harness内统一工作台，先接05/07，其余能力完成后逐项加入；不另做独立应用 | 用户集中Q08答复“Harness内统一工作台” |
| UI-PF-02 | bundle＋本地profile负责已审组件组合，原生面板负责入口/非秘密状态；聊天/Provider及底层业务继续由所属Host/模块拥有 | 设计决定，落实已确认统一入口 |

用户旅程：在Harness打开工作台→看到当前项目/会话与实际模块状态→进入记忆或上下文→返回聊天→必要时查看诊断/组合差异和待处理结果。未实际完成的能力显示后续接入，不提供可执行假按钮；fixture与真实release清楚区分。

自动行为为本地状态聚合、版本/冲突校验和有界刷新。用户主动选择导航、组合预览与启停；Host只产导航intent，client完成面板选择才显示opened；skill/host_command首版显示已登记指令与复制入口。accepted和opened均不表示业务任务完成。

失败时显示缺服务、不兼容、忙碌或结果待核；切项目撤销旧导航和显示；停用08只清入口/监听，不删各能力数据或停止远端任务。组合更新写版本和journal，失败恢复上个已验证组合，不回滚业务数据。

可见产物：能力卡、入口、任务/异常状态、组合manifest与本地差异/恢复记录。首版不依赖全部八能力完成；后置右侧停靠、布局偏好及批处理。无市场下载、远程控制台、额外模型、通知上报、同步或隧道。真实API、DTO和UI需求映射见[软件设计](software-design.md)；后续局部变更不要求整份重做。
